# Research: posture, cloud, exposure and configuration analysis (vendor survey)

Date: 2026-11-23. Scope: what CSPM, CNAPP, exposure-management, appsec and appliance vendors check, what Kavach already does, what is missing and which gaps this round closed. Kavach is observation-only, offline and never contacts a cloud, host or link; ideas that need a collector, an API call, a scan or enforcement are listed as rejected.

## Honesty about sources

Search results and fetches in this pass came through summarising tools, not raw pages. Only two pages were fetched directly: the nginx.org security advisories page and the F5 community article "Security best practices for BIG-IP and BIG-IQ systems" (F5 DevCentral/community). Everything else below comes from web-search result summaries (title, snippet, tool synthesis) and is marked `[search]`. Claims with no fetched or searched support are marked `[unverified]` (general knowledge, to be checked before anyone relies on them). No vendor check library, CIS Benchmark text or numbering was copied; policy wording in the repository is original.

## Boundaries checked

Nothing added calls a cloud API, scans a host, fetches a link, executes submitted text, includes files or changes anything. Inputs are text the analyst sends; all parsers are bounded; the advisory table is local (optionally replaced by an operator file through `KAVACH_CONFIG_ADVISORIES`, read from disk, never fetched). Detection of attacks in logs, API discovery and bot detection were not touched (another workstream).
