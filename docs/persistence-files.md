# On-disk state files

`<store>` is the path given to the server flag `-state` (default `./data/findings.jsonl`; the container and Helm chart use `/app/data/findings.jsonl`). The agent credential registry is a separate flag, `-credentials` (default `./data/agents.json`). Every derived file below is `<store>` plus a suffix, so for the default it is `./data/findings.jsonl.exposure.json` and so on. Nothing is written anywhere else (no request field reaches a filesystem path; see [security-review.md](security-review.md)).

Unless a row says otherwise, files are written atomically (temp file + rename) with mode 0600. For most derived files, a missing or corrupt file is logged or ignored and treated as empty at startup. There are two stricter exceptions plus the moved-aside incident ledger to know about:

* `<store>.incidents`: a line that is not valid JSON no longer aborts startup. The file is moved aside to `<store>.incidents.corrupt-<unixtime>`, a log line says so, and the ledger starts empty. If the file cannot be moved, startup exits with a clear error (no panic).
* The credential registry (`-credentials`): invalid JSON is deliberately fail-closed. Startup exits with a clear error naming the file (not a panic, contents never printed) rather than starting empty, because an empty registry would silently drop every enrolled host credential. Restore from backup or move the file aside to re-enroll. A missing file is fine (empty registry).
* `<store>.events.telemetry`: a corrupt file is moved aside to `<store>.events.telemetry.corrupt-<timestamp>` and persistence restarts empty (see [telemetry-types.md](telemetry-types.md)).

The findings file itself is read line by line; lines that do not parse are skipped, and only the newest 1000 findings are kept in memory (the server is started with a 1000-finding window), although the file on disk keeps growing until the retention purge rewrites it.

| File | Holds |
|------|-------|
| `<store>.intel.json` | Threat-intel feed definitions, last-sync status, ETags, indicator expiries and the feed-sourced indicators (older files with a bare feed array still load) |
| `<store>.tuning.json` | Tuning history (applied and reverted exclusions are re-derived from it at startup) and digest definitions with schedule state |
| `<store>.alerts.json` | Alert rules (deliveries are in-memory and de-duplicated per finding) |
| `<store>.iocimport.json` | Indicators created by `POST /v1/ioc/import` (ids `imp-<hash>`): type, normalised value, source, TLP, `valid_from`/`valid_until`, severity, short description, and the sighting counter and last-seen time. Expired indicators stay here for audit (they only stop matching). Capped by the shared 20,000-indicator limit. Counters are flushed at most every 30 seconds and at shutdown, so a crash can lose a few sightings. Written atomically, mode 0600; a corrupt file is logged and ignored. See `docs/ioc-import.md` |
| `<store>.certfeeds.json` | Cache of the opt-in worldwide CERT advisory feeds (`KAVACH_CERT_FEEDS`): up to 300 normalised advisories and the last fetch time per feed. Served from cache; a feed that fails keeps its previous items. See `docs/cert-feeds.md` |
| `<store>.epss.json` | Cache of the opt-in FIRST EPSS feed (`KAVACH_EPSS_FEED=on`, default off): EPSS score and percentile only for CVEs matched on this install at the last refresh plus KEV CVEs (max 50,000), the model version, score date and fetch time. Served from cache; a failed refresh keeps the previous cache. See `docs/vuln-priority.md` |
| `<store>.workspace.json` | Saved searches, notes and the hash-chained analyst journal (alert-rule changes are journaled here) |
| `<store>.posturetrend.json` | Posture trend: snapshot interval/enabled config and up to 400 counts-only snapshots (compliance score, ATT&CK coverage, findings by severity, SLO error-budget remaining, rule health counts). No finding text, host names or credentials. Written atomically (mode 0600) after each snapshot and flushed on shutdown via the lifecycle registry |
| `<store>.regulatory.json` | Regulatory profile: the regime ids the operator selected as applicable (`PUT /v1/regulatory/profile`), with update time and actor. Ids are validated against the embedded catalog on write; see `docs/regional-reporting.md` |
| `<store>.contentversions.json` | Content version history: up to 50 snapshots (seq, time, build string, per-pack hash and item count, per-item id, hash and per-field short hashes) of the embedded detection, byte-pattern, adversary, scenario, hunt and compliance packs, appended at startup only when content differs from the last snapshot. Served by `GET /v1/content/versions`, `/v1/content/changes?from=&to=` and `/v1/content/changelog`. Safe to delete (history restarts). Custom rules are not included. The blind-spot report (`GET /v1/coverage/blindspots`, `GET /v1/coverage/telemetry`) is computed live and stores nothing |
| `<store>.deception.json` | Deception canaries and trips |
| `<store>.customcontent.json` | Customer-authored detection content rules (full rule JSON including samples; see `docs/custom-content.md`). Every rule is re-validated at startup; rules that no longer pass are skipped |
| `<store>.scheduled_detections.json` | Scheduled detections (a saved search or kavach-seq query run on a 1 minute to 24 hour interval, recording findings as `hunt-<id>`): definitions, per-detection run history (retention configurable, default 50 runs), de-duplication keys, up to 100 shadow findings per detection in `testing`, hunt quota overrides (`PUT /v1/hunts/limits`) and the refusal log. Quota env defaults: `KAVACH_HUNT_MAX_SCHEDULED` (50), `KAVACH_HUNT_MAX_RUNS_PER_HOUR` (120), `KAVACH_HUNT_MAX_MATCHES_PER_RUN` (100), `KAVACH_HUNT_HISTORY_RETENTION` (50). Observation only |
| `<store>.exceptions.json` | Rule exceptions with mandatory expiry (max 365 days; scope = rule glob, optional host glob and executable glob, plus reason and owner), the last 1000 suppressed findings (reporting is suppressed, nothing is blocked) and the hash-chained create/update/expire/delete history (capped at 5000 entries) |
| `<store>.rulelifecycle.json` | Rule lifecycle states (draft/testing/production/retired), the hash-chained rule change history (custom rule edits and lifecycle changes; capped at 5000 entries) and up to 500 shadow findings from rules in `testing`. Lifecycle only affects reporting and ordering, plus the shadow recording; see `docs/rule-health.md` |
| `<store>.mlbehaviour.json` | Fleet-learned local behaviour models (`docs/local-models.md`): process-lineage transition counts (basenames only, per host and fleet, capped at 64 hosts / 1,000 and 5,000 edges), per-host reservoirs of up to 128 hashed 3-5-gram command vectors (64 non-zero features each, 32 hosts; never raw command lines), per-host hour-of-week EWMA baselines with a bounded hashed destination set, and the ingest tail cursor. Typically under 5 MB. Reset with `POST /v1/ml/reset` or delete the file while stopped; rebuild with `POST /v1/ml/learn/replay` |
| `<store>.mlext.json` | Extended local models (`docs/local-models.md`, section Extended models): per-host 5 minute DNS/domain windows (capped 64 registrable domains each, hashed subdomain sets of at most 128, up to 20 flagged windows per host, 128 hosts), per-user logon-hour histograms, hashed host sets (64) and executable basename counts (200; 256 users), per-host executable and destination count maps (200 each, 128 hosts) for the peer model, and the ingest cursors. No command lines. Typically under 5 MB. Reset with `POST /v1/ml/reset` or delete the file while stopped; rebuild with `POST /v1/ml/learn/replay`. The alert-fatigue model keeps no state |
| `<store>.feedback.json` | Analyst feedback loop (`docs/research-feedback.md`): append-only, hash-chained verdicts (true_positive, false_positive, benign_expected, needs_more_data) with actor, time, finding id, rule and host; capped at 100,000 entries (oldest dropped). A retraction is a new verdict, never a rewrite. Per-rule precision is derived on read; nothing is auto-applied. Verify with `GET /v1/feedback/verify`. Delete only while stopped |
| `<store>.regression.json` | Continuous control validation (`docs/regression-tracking.md`): config (daily HH:MM UTC, thresholds), up to 90 result snapshots (per-scenario, per-technique and per-tactic outcomes, benign false positives, runtime, fired rule ids) and up to 20 trimmed content snapshots (detection, byte-pattern and scenario items) used only for cause attribution. Safe to delete (history restarts; the next start runs once) |
| `<store>.beacon_allowlist.json` | Optional, read-only: extra destinations the beacon detector (`GET /v1/ml/beacons`, `docs/local-models-net.md`) should ignore, on top of the built-in NTP, OS-update, CDN and OCSP list. Kavach never writes it; create it by hand to tune beacon noise |
| `<store>.reportschedules.json` | Scheduled report definitions (template, params, frequency, retention, format, next/last run; max 100). Rendered reports live in the directory `<store>.reports/` as `<run_id>.md|json|csv` plus `<run_id>.meta.json` (template, params, generated_at, bytes, sha256, status), capped per schedule by retention, and globally at 500 reports / 64 MB. Pull-only via `GET /v1/reports/archive/{run_id}`; Kavach never emails or pushes reports. Deleting a schedule deletes its reports |
| `<store>.fleetslo.json` | Fleet SLO targets and the bounded series (5-minute samples, max 72 h, 500 agents: heartbeat freshness flag and event count per sample), persisted at most every 10 minutes. Derived only from data agents already send |
| `<store>` (the path itself) | The findings store: one JSON finding per line, appended; rewritten by the retention purge |
| `<store>.incidents` | Append-only JSON-lines incident workflow ledger (finding id, status, actor, time). Feeds `GET /v1/incidents` and the SOC metrics (`docs/observability.md`). A corrupt file is moved aside to `.corrupt-<unixtime>` and the ledger restarts empty, see above |
| `<store>.transitions` | Append-only log of detection-triage status transitions, merged with `.incidents` when computing MTTA/MTTR (`GET /v1/soc/metrics`) |
| `<store>.events.telemetry` | Ring buffer of typed telemetry (registry, dns, auth, module; 5000 per type; `docs/telemetry-types.md`). Corrupt file is renamed aside at startup |
| `<store>.events` | Append-only JSON-lines ledger of process, network and file events (retention purge rewrites it; contains full command lines and paths, so treat as personal data) |
| `<store>.cases.json` | Incident cases (title, severity, status, assignee, comments, linked findings), written atomically |
| `<store>.casetemplates.json` | Custom case templates, per-case workflow (checklist, applied template), chain-to-case links and a hash-chained journal of workflow actions |
| `<store>.hunts` | Hunt-pack schedules, run history and sequence counter (written non-atomically; mode 0600; no `.json` suffix) |
| `<store>.labrules.json` | Detection-lab rules (sandbox detection-as-code; shadow only, never promoted automatically) |
| `<store>.posture.json` | Posture assets and baselines (`GET /v1/posture/*`) |
| `<store>.vulncache.json` | Vulnerability feed cache: CISA KEV (CVE to date added, fetch time), OSV lookups per ecosystem/package/version, and matched advisories; 24 h TTL, opt-in network feeds. See `docs/vuln-feeds.md` |
| `<store>.exposure.json` | Software exposure state (`docs/exposure.md`): per-host SBOM component metadata (name, version, purl, type only; no hashes or licences) and the optional operator-imported advisory set. Written atomically, mode 0600. Safe to delete (SBOMs must be re-ingested; the embedded sample set returns) |
| `<store>.inventory.json` | Live inventory rows per domain so inventory APIs are not empty after restart. Location can be overridden with `KAVACH_INVENTORY` |
| `<store>.retention.json` | Data-governance retention policy (days per class: findings, process_events, network_events, file_events; null = unlimited) |
| `<store>.redaction.json` | Data-governance export redaction toggle (`{"enabled": bool}`) |
| `<store>.governance.audit.jsonl` | Append-only JSON-lines audit of governance actions (retention.set, retention.apply, redaction.set) with actor and time |
| `<store>.evidence.json` | Opt-in (`KAVACH_EVIDENCE_PERSIST=1`) metadata of offline evidence import cases (`docs/evidence-import.md`): up to 20 cases with id, labels, artefact inventory counts, totals and a findings summary (rule, severity, technique, artefact, line). Never holds raw artefact text, commands, paths, IOC values or the timeline; restored cases cannot be promoted. Safe to delete |
| credential registry file (`-credentials`, default `./data/agents.json`) | Agent enrollment (SHA-256 hashed credentials, never the plain secret) and last heartbeat; fleet health is derived from it, so stale detection survives restarts. Written by temp file + rename. Invalid JSON is a startup error |

Backup: copy these files while the server is stopped, or at any time (JSON state files are written by atomic rename; the append-only `<store>`, `<store>.events` and `.governance.audit.jsonl` files and `<store>.hunts` are not).


## Quick reference: files added with the newest features

| Feature | File | Reset | Doc |
|---|---|---|---|
| Extended local models (DNS, user logon hours, peer groups) | `<store>.mlext.json` | `POST /v1/ml/reset` (admin token or session; `kavachctl ml reset --yes`), then `POST /v1/ml/learn/replay` or delete while stopped | [local-models.md](local-models.md), [local-models-net.md](local-models-net.md) |
| Posture trend snapshots | `<store>.posturetrend.json` | Delete while stopped; history restarts, first snapshot about 15 s after start | [posture-reports.md](posture-reports.md) |
| Software exposure (SBOM metadata, operator advisories) | `<store>.exposure.json` | `DELETE /v1/exposure/sboms/{host}`, `DELETE /v1/exposure/advisories`, or delete the file while stopped | [exposure.md](exposure.md) |
| Fleet SLO series | `<store>.fleetslo.json` | Delete while stopped | [observability.md](observability.md) |
| Evidence import metadata (opt-in `KAVACH_EVIDENCE_PERSIST=1`) | `<store>.evidence.json` | Delete | [evidence-import.md](evidence-import.md) |

Cloud audit ingest (`POST /v1/cloud/audit/events`, [cloud-audit.md](cloud-audit.md)) has no file of its own: accepted records become ordinary findings in `<store>`. SBOM and cloud-audit bodies are not retained beyond the metadata described in the table.

## Operating notes

* **Backup**: see the paragraph above; the simplest consistent backup is to stop the server (or snapshot the volume) and copy `<store>*` plus the credentials file.
* **Restore**: stop the server, put the files back with mode 0600 and the same prefix, start. Files for features that are off (for example `.epss.json`) can simply be absent.
* **Disk growth**: `<store>`, `<store>.events` and the append-only ledgers grow until the retention purge (`POST /v1/governance/retention/apply`, admin token plus `{"confirm":"purge"}`) or external rotation. Size the Helm `persistence.size` (default 2 Gi) accordingly.
* **Personal data**: `<store>.events` contains full command lines and paths; treat it as personal data (see the governance endpoints in [observability.md](observability.md)).
* **Shutdown flush**: on SIGTERM the server stops background workers through the lifecycle registry within a 5 s budget after a 7 s HTTP drain; workers that persist on stop (for example the posture trend) flush then. A hard kill can lose the last interval of in-memory-only state.
