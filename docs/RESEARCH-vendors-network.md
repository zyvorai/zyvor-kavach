# Research: network security vendors and tools, and what Kavach should add

Researched 2026-11-23. Research only; the build that followed is [network-detection.md](network-detection.md). Scope: next-generation firewalls, SASE and proxies, NDR and traffic analysis, open network security monitoring, DNS security, DDoS and WAF edge, and the detection literature. Kavach is observation only and offline: it never contains, never calls a cloud, identity or threat-intelligence API, never scans a host, never captures packets and never fetches a link. It analyses logs that users send it. Earlier research that this document builds on and does not repeat: [RESEARCH-vendors-detection.md](RESEARCH-vendors-detection.md) (endpoint, WAF, NDR marketing and Zeek SSH brute force), [RESEARCH-vendors-posture.md](RESEARCH-vendors-posture.md) and [RESEARCH-vendors-identity-intel.md](RESEARCH-vendors-identity-intel.md).

How to read the evidence. **[fetched]** means a page was fetched on the date above and the statement was read there. **[search]** means a search-result summary only. **[U]** means unverified: general knowledge that no fetched page confirmed, to be checked before anyone relies on it. Vendor claims (accuracy, coverage, "days before disclosure") are the vendors' and were not tested. Fetches that returned only navigation text, redirects or 404 are marked as such rather than summarised.

## 1. Log formats that matter for an offline tool

| Source | Format and fields read | Evidence |
|---|---|---|
| Zeek (open) | Tab-separated logs with `#separator`, `#set_separator`, `#empty_field`, `#unset_field`, `#path`, `#fields`, `#types` headers; or one JSON object per line. conn.log: `ts uid id.orig_h id.orig_p id.resp_h id.resp_p proto service duration orig_bytes resp_bytes conn_state missed_bytes history orig_pkts resp_pkts orig_ip_bytes resp_ip_bytes`; `SF` is a normal establishment and termination. ssl.log carries `version cipher curve server_name resumed established subject issuer validation_status cert_chain_fps ja3 ja4` (ja3/ja4 only with the corresponding package) among about forty fields. dns, http, ssh, notice, weird, x509, files, smb, kerberos, dce_rpc follow the same header scheme. | conn.log and ssl main.zeek pages **[fetched]**; other logs' fields **[U]** |
| Suricata EVE JSON | One JSON object per line with `timestamp event_type flow_id src_ip src_port dest_ip dest_port proto app_proto`. Event types include `alert anomaly fileinfo http flow dns tls ssh smb krb5 rdp ftp dhcp quic ...`. `alert.signature`, `alert.signature_id`, `alert.category`, `alert.severity`, `alert.action` (allowed or blocked); `flow.bytes_toserver`, `flow.bytes_toclient`, `flow.age`, `flow.state`; `dns` with `rrname rrtype rcode answers`; `tls` with `sni subject issuerdn notbefore notafter ja3 ja3s ja4`. | EVE reference page **[fetched]** (the page was truncated after about 100,000 characters) |
| AWS VPC flow logs | Space-separated; default (version 2) record is `version account-id interface-id srcaddr dstaddr srcport dstport protocol packets bytes start end action log-status`; later versions add `vpc-id subnet-id instance-id tcp-flags type pkt-srcaddr pkt-dstaddr ... flow-direction traffic-path`; `-` marks not applicable; `action` is ACCEPT or REJECT; `log-status` OK, NODATA, SKIPDATA; aggregation interval 1 or 10 minutes. | AWS documentation **[fetched]** |
| Azure NSG flow logs | JSON `records[].properties.flows[].flows[].flowTuples[]`, each tuple a comma list `time,srcIP,dstIP,srcPort,dstPort,T|U,I|O,A|D` plus, in version 2, `B|C|E,pktsSent,bytesSent,pktsRecv,bytesRecv`. **NSG flow logs retire on 30 September 2027 and no new ones can be created; virtual network flow logs replace them.** Kavach supports the NSG form because exports exist; the VNet flow log schema was not researched. | Microsoft Learn **[fetched]** |
| NetFlow v5/v9, IPFIX, sFlow | Binary on the wire. Kavach reads only CSV exports (for example nfdump-style `ts,te,td,sa,da,sp,dp,pr,ipkt,ibyt`). Binary decoding, templates and sampling-rate correction are out of scope. | column names from general knowledge **[U]** |
| Palo Alto PAN-OS syslog | CSV. TRAFFIC order starts `FUTURE_USE, Receive Time, Serial Number, Type, Threat/Content Type, FUTURE_USE, Generated Time, Source Address, Destination Address, NAT Source IP, NAT Destination IP, Rule Name, Source User, Destination User, Application, Virtual System, Source Zone, Destination Zone, Inbound Interface, Outbound Interface, Log Action, FUTURE_USE, Session ID, Repeat Count, Source Port, Destination Port, NAT Source Port, NAT Destination Port, Flags, Protocol, Action, Bytes, Bytes Sent, Bytes Received, Packets, Start Time, Elapsed Time, Category`; Action is allow, deny, drop, drop ICMP, reset both, reset client, reset server. THREAT, CONFIG and SYSTEM field positions beyond the common prefix are not from the page. | traffic fields **[fetched]**; THREAT, CONFIG, SYSTEM **[U]** |
| Fortinet FortiGate | `key=value` syslog with `date time devname devid logid type subtype level srcip dstip srcport dstport proto action policyid sentbyte rcvdbyte logdesc msg user cfgpath cfgattr`. The fetched documentation page was navigation only. | **[U]** (fetch returned no field text) |
| Cisco ASA / FTD | `%ASA-<severity>-<id>: text`. 106023 is the ACL deny message **[search]**; 106100 reports an ACL permit or deny **[search]**; 302013 reads as a built inbound TCP connection **[search]**; 313001 and 710003 are denied connections to the box **[search]**. 113005, 605004, 611102, 111008, 111010 and 502103 as authentication failures and configuration or privilege changes **[U]**. | search summaries; the Cisco syslog guide itself was not fetched |
| Check Point, Juniper SRX, Sophos, WatchGuard, SonicWall, pfSense/OPNsense | Check Point Log Exporter (syslog and CEF/LEEF), Juniper `RT_FLOW_SESSION_CREATE/CLOSE/DENY` structured syslog, Sophos XG key=value, WatchGuard and SonicWall key=value, pfSense/OPNsense filterlog CSV. None fetched. | **[U]** all |
| Cloudflare Gateway DNS (Logpush) | Fields `Datetime AccountID QueryName QueryTypeName RCode ResolverDecision PolicyID PolicyName SrcIP DstIP ResolvedIPs ResponseTimeMs LocationID DeviceID QueryID`. | **[fetched]** |
| Cisco Umbrella DNS logs | CSV in S3; the documentation URL redirected and the new page was not read. | **[U]** |
| Zscaler ZIA NSS | Customisable feed output format; the fetched page was empty. | **[U]** |
| JA3, JA3S and JA4 | JA4 is a TLS client fingerprint of the form `a_b_c` (example `t13d1517h2_8daaf6152771_cb7bf5808d99`) that sorts ciphers and extensions to resist randomisation. JA4 itself is BSD 3-Clause; the other JA4+ methods (JA4S, JA4H, JA4X, JA4SSH, TCP, DHCP, ...) are patent-pending under the FoxIO License 1.1, which allows internal business use but not monetisation, and selling them in a product needs an OEM licence. JA3 is the older MD5 of client hello fields, broken by extension randomisation in modern clients **[U]**. | FoxIO README **[fetched]**; JA3 caveat **[U]** |

## 2. Vendors and tools: notable detections

All vendor rows below are **[U]** unless a source is given: the budget of this pass went to log formats and the detection literature, and the vendor marketing pages that were fetched in the earlier research ([RESEARCH-vendors-detection.md](RESEARCH-vendors-detection.md)) were not fetched again.

| Family | Vendors and tools | Detections worth borrowing (concept only) |
|---|---|---|
| NGFW | Palo Alto PAN-OS and Cortex, Fortinet FortiGate and FortiAnalyzer, Check Point, Cisco Secure Firewall (ASA, FTD), Juniper SRX/ATP, Sophos, WatchGuard, SonicWall, pfSense/OPNsense | Deny and drop counting per source; threat logs with severity and action (allowed or alert-only threats are the interesting ones); configuration and admin audit logs; zone and rule-hit analysis. These are logs, and logs are what Kavach can read. Inline prevention, App-ID and sandboxing are enforcement and out of scope. |
| SASE, SSE, proxy | Zscaler ZIA and ZPA, Netskope, Cloudflare Gateway, Cisco Umbrella, Squid | Per-user web and DNS decisions, threat-name and risk-score fields, newly observed or uncategorised destinations (a vendor category feed; Kavach has none). Squid `access.log` is already readable by the existing web-log parser. |
| NDR | Darktrace, Vectra AI, ExtraHop, Corelight, Arista NDR, Gigamon, Stamus | Beaconing and C2 (Vectra names intermittent beaconing and encrypted C2 **[search]**), per-network baselines (Darktrace "pattern of life", ExtraHop peer groups **[fetched earlier]**), east-west lateral movement, entity-grouped alerts (Corelight Investigator **[fetched earlier]**). The baseline products learn over weeks; Kavach sees one supplied window, so only within-window statistics are honest. |
| Open NSM | Zeek, Suricata, Snort, ntopng, Arkime | Zeek: scan, SSH guessing (30 failures, second notice on later success, **[fetched earlier]**), weird, notices. Suricata: signatures with classification and severity; EVE alerts, flows, anomaly events. Arkime and ntopng are packet or flow stores; their exports are flow-shaped. The scan script page for Zeek returned 404, so its default thresholds were not confirmed. |
| DNS security | Umbrella, Cloudflare Gateway, Infoblox, Quad9, DNS firewalls | DGA, tunnelling, newly seen or newly registered domains, fast flux, NXDOMAIN storms. Newly registered needs registration data and reputation needs a feed: neither is available offline, so those two are excluded (see section 5). |
| DDoS and WAF edge | F5, Cloudflare, Akamai, Imperva | Covered by [web-detection.md](web-detection.md) for access logs. |

## 3. The detection literature

| Topic | What was read | Takeaway for Kavach |
|---|---|---|
| RITA (Active Countermeasures) | README lists beaconing, long connections, DNS tunnelling and threat-intel checks **[fetched]**. The beacon score formula is not given on the page; the company's series on C2 beacons describes histograms of connection intervals, skewness, median absolute deviation (MAD), data smoothing and "delay and jitter" **[search]**. | Interval statistics are the accepted approach. Kavach uses the median interval and MAD relative to it, plus the share of intervals within a band of the median. Exact RITA weights were not available and are not claimed. |
| Jitter and frequency analysis | Vectra: jitter randomises each gap but not the underlying schedule; a Fourier transform can reveal the check-in frequency **[search]**. A Varonis article on the "jitter trap" says constant sleep times are found by low standard deviation of time differences **[search]**. A community note uses a coefficient of variation below 0.20 as a periodicity threshold (not a standard) **[search]**. | Wide-jitter beacons are missed by the relative-MAD test. A frequency-domain detector is a known extension and is listed under ideas. |
| MITRE ATT&CK network techniques | T1071 (and .004 DNS), T1568 (.001 fast flux, .002 DGA), T1572, T1573, T1571, T1095, T1046, T1021 (.002 SMB), T1048, T1041, T1110, T1595, T1499, T1562.004 | All used or already in the guidance catalog. T1568, T1568.001, T1568.002 and T1562.004 were added to the catalog by this work. |
| Port scan and brute-force heuristics | Zeek's guesser model (count then flag a later success) is the open reference **[fetched earlier]**. | Fixed windows and distinct-target counts; thresholds chosen for a summarised log and documented as such. |
| Lateral movement and exfiltration analytics | NDR vendors flag fan-out to many internal hosts on SMB, RPC, RDP and WinRM, and unusual outbound volume **[U]**. | Fan-out counts per window, and outlier detection over per-pair byte totals using median and MAD (robust to a few huge values) instead of mean and standard deviation. |

## 4. What Kavach already had

Host-side DNS, beacon and fast-flux models for Netra telemetry ([local-models-net.md](local-models-net.md), `ml_net_*`, `ml_ext_dns.go`); an agent DNS telemetry type; the web access-log, authentication-log, identity-provider and ransomware-log analytics ([web-detection.md](web-detection.md), [identity-detection.md](identity-detection.md), [ransomware-logs.md](ransomware-logs.md)); firewall rule review of submitted configuration ([firewall-rule-review.md](firewall-rule-review.md)); IOC import and matching; tripwires; attack paths. What was missing: any reader for Zeek, Suricata, cloud flow logs, NetFlow CSV or firewall logs; any DNS query-log analytics that works from a log rather than from the agent; beaconing, scan, fan-out and exfiltration statistics over a supplied connection log; and a joined view of existing findings by address, host and time.

## 5. Ranked ideas

| Rank | Idea | Why | Verdict |
|---|---|---|---|
| 1 | Zeek ingestion (TSV and JSON) with beaconing, long connections, scans, SSH guessing, certificate and JA3/JA4 checks, SMB admin shares | Zeek is the most common open NSM output and every NDR vendor's detections reduce to its fields; the logs are small and structured | **Built** |
| 2 | Suricata EVE ingestion: alerts grouped by source and category with ATT&CK mapping, alert storms, top talkers and signatures | Suricata alerts are the most common network alert source; grouping by entity is what Corelight and Stamus do | **Built** |
| 3 | DNS query-log analytics: DGA-like names, tunnelling, NXDOMAIN storms, fast flux | DNS logs are the cheapest network telemetry; Umbrella, Gateway and Zeek all produce them | **Built** (newly seen domain deliberately not built) |
| 4 | Flow-log analytics: VPC, NSG, NetFlow CSV; exfiltration outliers, rare ports, scans, fan-out, operator address lists | Cloud flow logs are the only network telemetry many cloud estates have | **Built** |
| 5 | Firewall log subset: PAN-OS CSV, FortiGate key=value, ASA message ids; deny storms, allow after deny, alert-only threats, configuration change and admin login failures | Every NGFW vendor emits these and the audit events matter | **Built** (subset, unverified against real devices) |
| 6 | Evidence timeline joining findings by address, host and window | NDR products sell the entity-grouped story; the data already exists in the store | **Built** (exact joins only) |
| 7 | Frequency-domain (Fourier) beacon detection for jittered beacons | Catches what relative MAD misses | Not built: needs tuning against real captures |
| 8 | Check Point, Juniper SRX, Sophos, WatchGuard, SonicWall, pfSense parsers | Breadth | Not built: field names are unverified **[U]**; a wrong parser is worse than none |
| 9 | Binary NetFlow v5/v9, IPFIX and sFlow decoding | Fidelity | Not built: Kavach is a log analyser, template handling and sampling correction are a separate product |
| 10 | Newly registered or newly seen domain detection | A strong DNS signal | Rejected: needs registration data or a reputation feed, which means an external lookup. Within one log "first seen in this log" says nothing about age |
| 11 | JA3/JA4 reputation (abuse.ch SSLBL, FoxIO databases) | Known-bad fingerprint matching | Rejected as built-in content: Kavach never fetches; it matches a list the user supplies. JA4+ non-JA4 methods carry a non-commercial-style licence |
| 12 | Kerberos, NTLM and RDP Zeek logs for kerberoasting and pass-the-hash analytics | Strong identity signals | Deferred: needs per-field research; kerberos and ntlm records are counted and otherwise ignored |
| 13 | Threat-intel enrichment, geo or ASN lookups, WHOIS, passive DNS | Context | Rejected: external lookups |
| 14 | Blocking, sinkholing, quarantine | Response | Rejected: Kavach is observation only |
