# Evidence-based vulnerability prioritisation

Kavach is observation-only. These endpoints rank the CVEs already matched on your hosts using the CISA SSVC decision tree plus optional EPSS evidence. They give advice; nothing is patched. `/v1/vulns/top` and all other existing endpoints are unchanged. Research and citations: `docs/research-vuln-priority.md`.

## Endpoints (all require auth)

- `GET /v1/vulns/priority?host=&limit=` : matched CVEs (per host and package), ranked by SSVC outcome (Act, Attend, Track*, Track), then EPSS (unknown last), then CVSS, then CVE/host/package so the order is deterministic. `limit` 1-500, default 50. Each item has `factors` (value, source, `known`, `assumed_value` and evidence per decision point), the `ssvc` evaluation, and an `explanation` list.
- `GET /v1/vulns/priority/{cve}` : every host where the CVE matched, with the full explanation. 400 for a malformed id, 404 if unmatched.
- `GET /v1/vulns/priority/status` : EPSS feed status, tree version, thresholds, default assumptions and limitations.
- `POST /v1/vulns/priority/refresh` : refresh EPSS now; 409 when the feed is off.

## Decision points and sources

| Decision point | Value source |
|---|---|
| Exploitation | `active` if the CVE is in CISA KEV (needs `KAVACH_VULN_FEED=kev`; KEV always wins). `poc` if cached EPSS >= 0.10 (Kavach policy, not from SSVC or FIRST). Otherwise `unknown`, including for low EPSS |
| Automatable | `unknown` unless the advisory (in `KAVACH_CVE_FILE`) carries a `cvss_vector`; then `yes` for AV:N/AC:L/PR:N/UI:N (v4 also AT:N, or the AU metric verbatim), else `no`. An approximation |
| Technical impact | From the same vector: `total` if C:H and I:H (v4 VC:H and VI:H), else `partial`. An approximation |
| Mission prevalence | Host criticality from `/v1/posture/assets` (read from `<store>.posture.json`): 4-5 `essential`, 3 `support`, 1-2 `minimal`, unregistered `unknown` |
| Public well-being impact | Always `unknown` (Kavach has no such data) |

The tree is Table 8 and Table 9 of the CISA SSVC Guide (Nov 2022), version string `cisa-ssvc-2022-11/table9`. CISA's tree has no "unknown" value and tells analysts to assume the most reasonable value. Kavach keeps the input marked `unknown`, applies the default (exploitation none, automatable no, technical impact partial, mission support, well-being minimal) and reports `outcome_if_unknowns_favourable` and `outcome_if_unknowns_adverse` plus `outcome_depends_on_unknowns`, the range over every possible true value.

## EPSS feed (opt-in)

- Default off. `KAVACH_EPSS_FEED=on` enables it; no network traffic otherwise.
- One request: plain `GET https://epss.empiricalsecurity.com/epss_scores-current.csv.gz` (the daily bulk file FIRST points to). Only that host over https is allowed; up to 3 redirects, re-checked. The request carries no query string, body, credentials, host names, package names or CVE ids, only `User-Agent: kavach-epss-feed`. A test asserts this.
- The file is filtered locally to CVEs matched on this install plus KEV CVEs (cap 50,000), so FIRST never learns which CVEs matched.
- Limits: 30 s timeout, 16 MiB compressed, 64 MiB decompressed. Refresh at start and every 24 h; requests never block on the network. A failure keeps the previous cache and appears in `feed_errors`.
- Cache: `<store>.epss.json` (see `docs/persistence-files.md`), with model version and score date from the file's `#` header.
- Terms: FIRST publishes the data free with no registration and requests attribution; no licence text was found. Attribution is returned in the status output: "EPSS is maintained by the EPSS Special Interest Group at FIRST. Scores are generated by Empirical Security and published freely to the community."

## Honest limits

- EPSS is a modelled probability of exploitation activity in the next 30 days. It says nothing about impact, is global rather than specific to you, and must not be multiplied with CVSS.
- SSVC needs organisational context (mission prevalence, public well-being). The demo has at most a 1-5 asset criticality, so many outcomes depend on unknowns; check the outcome range.
- Automatable and technical impact are approximations from CVSS vectors, and only when a vector is available.
- A low EPSS or missing KEV entry is not evidence that no exploit exists.
- EPSS for a CVE that first matched after the last refresh is `unknown` until the next refresh.
- The embedded advisory set is a small sample unless `KAVACH_CVE_FILE` or `KAVACH_VULN_FEED` is set.
- The 0.10 EPSS threshold is a policy choice that has not been tuned or validated.
